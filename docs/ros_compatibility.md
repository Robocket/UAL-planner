# ROS 开发边界

当前分支处于学习模型选型阶段，尚未实现 ROS 节点。

- 当前算法层仅以 RGB 图像/短序列为环境输入，按选定模型输出深度、局部点云及可能的相机几何，独立于 ROS。
- 图像实例分割作为单独能力保留；不假定重建模型会输出船舶/甲板实例标签。
- 训练、评测与模型导出使用独立 Python 环境，不依赖 Jazzy 或 Noetic 的消息 API。
- Jazzy 包装负责消息转换、时间戳、QoS、参数和发布。
- Noetic 使用独立 `roscpp/rospy` 包装与 `.launch`，复用同一推理核心。
- 图像、可选里程计、相机标定、窗口/缓存、同步和类别映射通过根目录 `config` 配置。
- 雷达及雷达 IMU 不进入实时重建/分割。离线雷达评测不得反向给模型提供深度、尺度或在线几何。
- 现有里程计仅是默认关闭的可选世界/尺度辅助；启用前核验来源，分别记录 RGB-only 与辅助模式的结果。
- 模型局部/重建坐标及尺度必须显式标记；可靠尺度和世界变换尚未建立时不发布为真实世界坐标。
  下游统一世界坐标的目标保留，转换须使用核验后的对应时刻姿态、相机外参及明确的轴约定。
- Noetic 与 Jazzy 的 bag 格式及自定义消息不同，仅切换 launch 不能解决离线数据转换。
  两侧图像适配器应输出相同数值接口；当前没有迁入旧驱动、旧投影或旧分割实现。
- 模型 demo 的视频/图像目录输入不等于已接入 ROS 话题；在线结果需保留输入时间戳，并记录处理延迟与结果年龄。
- 在线窗口/地图应有有界缓存、跳帧与过期策略，不能通过无限累积结果掩盖处理积压。

不同 launch 负责选择包装和设备配置；不能让 ROS 2 节点自动兼容 ROS 1。
后续 ROS 包构建可使用 `scripts/build_jazzy.sh`；当前没有可构建的 ROS 包。
