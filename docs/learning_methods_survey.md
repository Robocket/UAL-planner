# 纯视觉模型驱动的在线三维重建：选型与试验边界

初次调研日期：2026-10-09；场景匹配更新：2026-10-11。依据作者仓库、论文及官方模型说明。
用户已接受先试“在匹配海事数据上评测过、但未做船舶微调”的 MASt3R。
本机离线试验的环境、产物和边界见 [海事场景验证](maritime_scene_trial.md)。

## 1. 当前方向

根据用户最新要求，`learning-methods` 先尝试单相机纯视觉重建，不采用上一轮雷达融合检测路线。
船只优先，车辆作为后续类别保留，但当前没有自采车辆数据。二维框与实例分割需求继续保留。
不恢复旧 SAM3、雷达投影或实例尺寸变化测距实现，不在本轮添加降落控制算法。

这里的“依靠模型重建”指图像输入后预测深度、三维点或相机几何，再形成随时间更新的空间表示。
不等同于预测三维 bounding box，也不要求整个降落控制系统端到端训练。
原共享对话主要举例 Depth Anything V2 的深度估计及尺度局限，并未提供已验证的船舶实时重建实现。
下列项目是针对最新重建需求补充的选型，不能当成共享对话已确定的方案。

上一轮多模态项目与海事三维标注资料保留在 [历史参考](multimodal_detection_reference.md)，不作为当前开发任务。

## 2. 必须区分的三层输出

| 层级 | 输出 | 尚不能据此保证什么 |
| --- | --- | --- |
| 逐帧深度/局部重建 | 深度图、置信度、相机坐标下可见表面点云 | 不保证跨帧一致或绝对米制尺度 |
| 在线一致重建 | 连续相机轨迹、局部/全局地图、跨帧关联或融合 | 地图可能漂移，运动船只不能当作静态背景累积 |
| 降落目标感知 | 船舶实例框/掩膜、对应表面及后续甲板判断 | 整船外框不能直接代表平坦且无障碍的降落区域 |

本轮最终希望在线重建，但先用短序列验证模型几何与资源需求。
离线短序列成功、渲染流畅或模型前向快，都不能单独证明实时地图已实现。

## 3. 候选项目

下面的优先级是面向当前硬件的工程建议，所有船舶适用性都待 Scene_Water 验证。

| 项目 | 官方提供的能力 | 当前任务的限制 / 建议 |
| --- | --- | --- |
| Depth Anything 3 Small | 深度、相机参数、可选已知姿态条件输入；Small 为约 0.08B 参数，Apache-2.0 | 先做轻量短序列几何试验；Small 不属于官方米制模型，不是现成完整 SLAM |
| MASt3R-SLAM | 学习式点图先验 + 跟踪、局部融合、回环和全局优化；支持视频/图像目录及已知标定 | 最接近完整在线稠密 SLAM 的候选；作者实验用 RTX 4090，不保证 T600 实时 |
| SLAM3R | 从视频用网络直接回归三维点并进行局部到统一坐标的重建，提供 online 模式 | 与模型驱动重建相符，但含 Image-to-Points / Local-to-World 两模型；显存、漂移和动态船舶需实测 |
| StreamVGGT | 因果注意力与缓存支持增量视觉几何重建 | 可作为流式研究对照；缓存和注意力依赖、尺度及持续显存增长需单独核验，暂不优先上本机 |
| Depth Anything V2 Metric Small | 约 24.8M 参数的米制深度模型，官方有深度转点云脚本 | 资源受限时的逐帧局部几何基线；室外权重来自 Virtual KITTI，不能将车载域尺度准确率套到海上；不是在线 SLAM |
| Video Depth Anything | 相对/米制视频深度，提供 Small 及实验性流式推理 | 可改善时间一致性，但不提供完整相机轨迹/地图；作者报告流式较离线有精度下降，Small 也不意味着运行显存一定小 |

[MASt3R-SLAM 作者实现](https://github.com/rmurai0610/MASt3R-SLAM)、
[SLAM3R 作者实现](https://github.com/PKU-VCL-3DV/SLAM3R)、

[Depth Anything V2 米制模型](https://github.com/DepthAnything/Depth-Anything-V2/blob/main/metric_depth/README.md)、

### 推荐先试什么

现按场景匹配优先，将第一项试验改为 **MASt3R + MTReD + Scene_Water**。
MTReD 包含海上航拍船舶、岛屿与海岸，作者使用 MASt3R 作三维重建评测并提供脚本。
这支持先验证海面/船舶场景，不代表官方权重在 MTReD 上训练过。
它也没有真实三维真值，不能用重投影表现推断降落距离精度。
[数据与作者脚本](https://github.com/RuiYiYong/MTReD)、[论文](https://arxiv.org/html/2503.00853v1)

本轮仅使用官方 MASt3R 的两帧点图预测，既不是完整复现 MTReD 的多视图评测，也不是
MASt3R-SLAM。DA3-Small 仍是资源受限时的后续候选，不同时安装多条路线。
短窗口如何对齐、缓存、维护地图仍需后续设计，不能宣称调用一次 API 就得到在线一致重建。

如果用户首先需要的是完整持续建图，优先单独评估 MASt3R-SLAM，而不是将 DA3 短窗口结果
拼起来就称作 SLAM；若资源允许，再比较 SLAM3R。模型选择不预设需要自行训练。

### 官方“实时”数字的边界

- MASt3R-SLAM 项目报告约 15 FPS，仓库明确作者实验使用 RTX 4090。
  [项目页](https://edexheim.github.io/mast3r-slam/)、[硬件说明](https://github.com/rmurai0610/MASt3R-SLAM)
- DA3-Streaming 是分块长视频管线，作者明确它不是 SLAM 系统；公开 A100 测试约 8.51 FPS，
  不包含加载、预热和 PLY 保存。其公开 KITTI 最小列出的 30 帧块配置峰值显存为 11.5 GB，
  不能视为当前 4 GiB 显卡的现成默认方案。这些数字不是 DA3-Small 两帧试验指标。
  [官方 Streaming 说明](https://github.com/ByteDance-Seed/Depth-Anything-3/blob/main/da3_streaming/README.md)
- Video Depth Anything 公布的 Small FP16 显存约 6.8 GB，对应 A100 上 32 帧、518 × 518 的输入；
  与单帧流式配置不同，不能按参数量直接承诺可放入 4 GiB。
  [官方资源测试与流式限制](https://github.com/DepthAnything/Video-Depth-Anything)

## 4. 尺度、世界坐标与运动船只

### 纯视觉与里程计的边界

本轮环境几何仅来自 RGB 图像。bag 中的雷达/雷达 IMU 不进入重建或实例分割模型。
沿用此前可使用里程计的上下文，将 `/fsdk/aircraft_state` 仅保留为可选尺度/世界坐标辅助，
首轮图像模型试验默认不使用；它的生成来源也须核实，避免间接引入雷达信息。
严格 RGB-only 模式和外部里程计辅助模式必须分别记录，不能混报精度。

### 模型输出尺度不是距离真值

DA3-Small 官方模型卡没有米制深度能力；DA3 Metric / Nested 是另外的型号。
V2 Metric Small 虽输出米制深度，也仍依赖训练先验，对海面、俯视船舶和远距离的误差需要验证。
相机内参不能单独消除单目尺度不确定性。
[DA3 官方模型卡](https://github.com/ByteDance-Seed/Depth-Anything-3)、
[V2 米制模型训练域与输出说明](https://github.com/DepthAnything/Depth-Anything-V2/blob/main/metric_depth/README.md)

可靠外部里程计在足够运动、正确同步且有静态对应时可用于尺度/轨迹对齐；悬停、纯旋转，
或观测主要来自独立运动船只时不能保证可观测。这里仅记录后续验证条件，不实现新的尺度算法。

### 世界坐标发布规则

- 保留“下游空间计算统一世界坐标”的目标，但未建立可靠尺度和世界变换前，只输出明确标记的局部/重建坐标。
- 模型坐标不能仅改 frame_id 为 `world`。如使用里程计，需核验世界系、相机到机体系外参、时间及轴约定。
- 图像缩放/裁剪时同步变换内参和掩膜坐标；模型估计内参不直接替代已标定内参。
- DA3 API 的 extrinsics 按 world-to-camera 定义；不直接当作 camera-to-world，更不直接当作 FSDK 世界坐标。
  [官方 API 输出约定](https://github.com/ByteDance-Seed/Depth-Anything-3)
- 相机光学轴与机体轴不同，即使物理镜头同向也需要明确轴转换。
  [ROS REP-103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)

### 船只不能当作静态场景

海面反光、弱纹理、遮挡和船舶独立运动是本任务的主要风险。
仅补偿无人机运动再把船舶点云跨帧叠加，可能产生拖影；目标掩膜能提供关联范围，但不能替代船舶运动估计。
以上是工程风险判断，不是已经核实这些模型完全支持动态船舶。
首轮分别观察当前帧可见船体/甲板点云和静态背景结果，不将统一静态地图作为动态目标的几何真值。

## 5. 实例分割与目标框

重建模型并不直接提供当前要求的船舶/甲板实例标签，需要保留独立分割能力。
可继续比较公开 YOLOE 的 boat/ship 提示分割，及 RF-DETR / RTMDet-Ins 的任务微调。
[YOLOE 作者仓库](https://github.com/THU-MIG/yoloe)、
[RF-DETR 仓库](https://github.com/roboflow/rf-detr)、
[RTMDet 实例分割配置](https://github.com/open-mmlab/mmdetection/blob/main/configs/rtmdet/README.md)

当前不恢复 SAM3。整船框/掩膜、甲板掩膜和安全降落区域分别评估。
从掩膜对应可见点云得到的框不能默认是完整船体框；三维框作为后续派生结果，尚未实现。

## 6. 数据与实时评测

Scene_Water metadata 记录约 640 秒、5098 条压缩图像，平均约 7.96 Hz，
以及 32005 条 `/fsdk/aircraft_state` 里程计。实际瞬时帧间隔仍需读取时间戳核验。
相机输入为 `/left_camera/image/compressed`，1280 × 1024；历史内参尚未正式核验。

本机查询为 NVIDIA T600 Laptop、4096 MiB 显存。实时帧率目标暂未由用户指定；
先以不持续积压该 bag 的图像流为参考，完整链路能否稳定处理约 8 Hz 必须实测。

按下列顺序验证；已执行部分及测量值单独记录在场景报告：

1. 提取短片并保留原时间戳，划分停泊船、运动船、无人机运动及海面占比等测试条件。
2. 先单独测 MASt3R 的两帧点图，比较分辨率和资源需求，先不同时加载分割网络。
3. 记录冷启动、预热、预处理、GPU 前向、后处理、点云生成、发布/渲染的独立耗时和完整延迟。
   GPU 计时须同步，另记录峰值显存、持续增长、处理帧率与结果数据年龄。
4. 再加入实例分割，测总延迟与双模型显存；不能把分割单模型帧率当重建完整链路帧率。
5. 将已知尺度、米制真值或独立测量用于离线评测。bag 雷达仅可作为单独评测参考，默认禁用，
   不参与模型输入、在线尺度校正或世界几何生成；稀疏点云也不能直接当作完整船体/甲板真值。
6. 资源与几何通过后，再决定局部在线更新还是完整 MASt3R-SLAM / SLAM3R 路线，最后接 ROS 和 RViz。

结果至少包含深度/尺度误差、可见表面误差、跨帧抖动、重建漂移、目标漏检和按距离/视角分组的统计。
三维渲染好看不是降落精度证明，也不宣称模型能恢复不可见船底或微小甲板障碍。
长序列必须有有界窗口/缓存和明确过期策略；跳帧可降低负载，但需要同步报告更新频率与漏帧。

## 7. 接口和实现范围

根目录 `config/scene_water.yaml` 仍是数据契约与试验建议，不是可直接加载的 ROS 参数文件。
图像重建/分割核心独立于 ROS；Jazzy 与 Noetic 的包装负责消息、参数、QoS 和 launch。
不恢复旧雷达解码或投影链路，当前 `src` 无算法节点；离线试验仅在独立环境安装依赖/权重。
后续实时接入须自行包装图像流；作者的视频/图像目录 demo 不等于已经适配本项目相机话题。
