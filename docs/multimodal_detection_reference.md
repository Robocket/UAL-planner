# 历史参考：单相机 + 激光雷达的学习式三维检测

本报告保留上一轮多模态检测调研，不再代表当前试验方向，也不是实施清单。
用户已选择先尝试纯视觉模型重建；当前范围见 [纯视觉重建选型报告](learning_methods_survey.md)。

调研日期：2026-10-09。以下来源为上游项目仓库、作者论文或官方文档。
本报告是选型研究，尚未在本机安装或运行这些候选模型；不将论文指标当作 Scene_Water 实测结果。

## 1. 任务范围

根据用户最新确认，本分支从纯视觉方向调整为单相机 + 激光雷达的学习式三维目标检测。
降落目标暂定船只；车辆保留为后续类别，目前未收集车辆相关数据，不纳入首轮训练和实测。
此前的实例分割需求继续保留，不恢复原 SAM3、投影或几何框算法。
当前只更新需求、数据契约和选型研究；尚未选择最终模型、安装依赖或实施训练。

必须分别定义三种目标：

| 目标 | 学习模型需要输出什么 | 对后续使用的意义 |
| --- | --- | --- |
| 船舶整体 | 三维目标框；图像中的二维框和实例掩膜 | 远距离识别、定位和接近目标 |
| 甲板/降落平台 | 特定表面的框和实例掩膜 | 确定近距离降落目标区域 |
| 满足降落条件的区域 | 可用区域、障碍等标签及后续评价 | 需要任务标注与额外判断，不能由整船检测框直接替代 |

二维框使用图像像素坐标；三维框必须明确米制中心、尺寸、方向和参考坐标系。
完整船体框、可见表面点云框和甲板区域不能混用。对外目标空间信息统一到世界坐标；
学习网络可以在训练所用的局部坐标内计算，但不能直接把其输出改名为世界坐标。

## 3. 学习式三维检测候选与优先级

以下优先级是基于输入匹配、依赖和数据需求的工程判断，不是本机测试结果。

| 项目 | 输入 / 输出 | 本任务适用性与主要缺口 | 优先级 |
| --- | --- | --- | --- |
| MVXNet / MMDetection3D | 单相机图像 + 点云 + 标定 → 三维框 | 官方有 KITTI 单相机融合推理示例，适合作为融合基线；船舶类别、尺寸先验、点云范围与无人机视角需重新适配和训练；不自带所需实例掩膜 | 融合路线首轮候选 |
| PointPillars / OpenPCDet 或 MMDetection3D | 点云 → 三维框 | 用于验证不融合图像时的定位能力及计算成本；需要船舶三维标签和尺度适配；相机实例分割单独验证 | 首轮对照基线，不等于最终融合方案 |
| CenterPoint / OpenPCDet | 点云 → 三维框，部分配置含速度 | 可作为第二阶段对照；不能把车载数据上学到的速度或精度直接用于机动无人机上的船舶 | 第二阶段 |
| BEVFusion | 官方主要为 nuScenes 多相机 + 点云 → 三维框等 | 改为单相机需重新配置数据、训练和验证覆盖范围；原作者实现依赖较旧，不作为直接装入 Jazzy Python 环境的起点 | 暂后置 |
| 图像分割 + 目标点云关联 | 图像、点云、标定 → 掩膜及目标候选点 | 可保留为标注辅助或诊断对照；不等于学习网络直接预测三维框，也不能将框内全部点直接当目标 | 只作为可选对照，不恢复旧实现 |

来源：[MVXNet 配置与权重](https://github.com/open-mmlab/mmdetection3d/blob/main/configs/mvxnet/README.md)、
[官方单相机融合推理示例](https://mmdetection3d.readthedocs.io/en/latest/user_guides/inference.html)、
[OpenPCDet 模型与许可证](https://github.com/open-mmlab/OpenPCDet)、
[BEVFusion 配置与依赖](https://github.com/mit-han-lab/bevfusion)。

MVXNet 并不是最新架构，推荐它是为了先建立单相机融合的可复现基线。
本轮没有核实到可直接覆盖“无人机视角大型船舶 + 甲板实例掩膜”的上述三维预训练权重；
KITTI/nuScenes 道路权重可验证代码链路，不能仅将 Car 类改名为 Ship 就用于船舶检测。

PointPillars 部署可参考 NVIDIA 的 CUDA/TensorRT 实现，但自定义船舶类别、输入特征和范围
仍需与导出模型匹配；公开性能不代表当前硬件可达到的帧率。
[NVIDIA CUDA-PointPillars](https://github.com/NVIDIA-AI-IOT/CUDA-PointPillars)

## 4. 图像实例分割候选（仍需保留）

三维框模型和图像实例分割可以分别选型；未发现上述三维检测配置能直接满足甲板实例分割。
不要求两项能力一定由同一个大模型实现，也不以完成整套端到端驾驶网络为目标。

### YOLOE：公开预训练权重的首轮验证路线

YOLOE 支持文本、视觉示例和无提示词模式，具有检测与实例分割能力；上游提供预训练模型、
迁移学习和导出路径。建议以 `yoloe-11s-seg.pt` 为起点验证任务语义。
[作者仓库](https://github.com/THU-MIG/yoloe)

当前 Ultralytics 文档另列出 `yoloe-26n-seg.pt` 轻量候选，并说明固定提示可随模型导出到
ONNX/TensorRT。正式试验前需要固定库版本和权重版本。
[模型与导出文档](https://docs.ultralytics.com/models/yoloe/)

工程判断：适合尚无自定义标注数据时先尝试 ship/boat；ship deck、landing platform 等提示
仅是试验候选，不能保证识别出所需表面。零样本提示本身不等于在自己的数据上训练。

### RF-DETR 实例分割：监督学习/迁移学习候选

当前上游提供 RF-DETR 实例分割模型，包括 `RFDETRSegNano`、`RFDETRSegSmall` 等，预测结果
包含实例掩膜和框。Seg-Nano/Small 在上游表中标为 Apache-2.0；Plus 型号有不同许可证。
[官方仓库](https://github.com/roboflow/rf-detr)

官方提供使用自定义 COCO 格式数据进行微调和模型导出的流程。工程判断：如果要学习特定
船舶甲板或降落平台，可将这条路线列为重点；训练前需确认选定发布版支持所需分割 API。
[训练说明](https://rfdetr.roboflow.com/learn/train/)

预训练的常见物体识别能力不代表已有“可降落甲板”标签。只有框标注不足以训练实例掩膜，
自定义实例分割需要对应的轮廓或掩膜标注。

### RTMDet-Ins：另一条监督学习基线

RTMDet 配置提供实例分割预训练模型，以及通过 MMDeploy 导出 ONNX/TensorRT 的说明；
MMDetection 项目代码采用 Apache-2.0。
[模型与部署配置](https://github.com/open-mmlab/mmdetection/blob/main/configs/rtmdet/README.md)、
[项目仓库](https://github.com/open-mmlab/mmdetection)

工程判断：适合固定类别、可复现的训练对照；接入时应先核对 PyTorch/MMCV/MMDeploy 版本组合。
需要自定义降落目标时，同样依赖目标任务标注。

### RT-DETR：只作为目标框对照

作者仓库提供实时目标检测模型、预训练权重和训练实现。
[官方仓库](https://github.com/lyuwenyu/RT-DETR)

本次未核实该仓库提供与需求对应的原生实例分割链路，因此不作为“框 + 实例掩膜”的首选。

## 5. 专门面向无人机降落的项目

### SafeLand

公开部分是 ROS 2 航空图像语义分割模型，包含地面、水体、人、障碍等类别；仓库明确说明
未公开完整降落流水线。船舶类别的验证 IoU 标为 n/a，不能将其当成海上甲板识别证据。
[作者仓库](https://github.com/markus-42/SafeLand)

工程判断：可研究降落相关类别和场景理解；当前不是直接产生甲板实例框的完整项目。

### OpenLander

公开模型输出 obstacle、human、safe 三类像素分割；现有推理脚本依赖 Luxonis/DepthAI 设备，
包括用本地图像测试时也需要连接设备。
[作者仓库](https://github.com/stephansturges/OpenLander)

工程判断：任务方向贴近降落区域识别，但不能直接在现有海康相机 + NVIDIA 机器上原样运行。
迁移前必须核实模型格式与可用权重；语义区域转目标框也需要后处理。

## 6. ROS 接入参考

当前 `yolo_ros` 仓库列出 Jazzy 支持，并提供 C++/ONNX Runtime 检测、实例分割、跟踪和调试图像。
检测消息包含 bounding box，分割模型可附带掩膜。
[官方仓库](https://github.com/mgonzs13/yolo_ros)

它仅作为图像推理接入参考，不是单相机 + 激光雷达三维融合节点，也不负责学习“什么区域可以降落”。
YOLOE 的静态导出结果需要核对输出
布局；不能假定 RF-DETR/RTMDet 可直接套用 YOLO 解码器。

后续结构建议：离线训练/评测、无 ROS 推理核心、Jazzy/Noetic 包装分开维护。
所有设备接口在根目录配置，同一模型的数值计算不因 ROS 发行版改变。
Livox CustomMsg 解码、图像解压、时间匹配和坐标转换属于数据适配层；这些新适配尚未实现。

## 7. 推荐试验顺序（尚未执行）

1. 核验 Scene_Water 原始消息的时间戳、frame_id、点云单位/特征及里程计参考系，确认相机与雷达共同视场。
2. 定义整船三维框与甲板/平台实例标签，先保留独立测试序列；车辆暂不加入自采训练集。
3. 评估 SeePerSea 的数据访问、标注和许可证，再固定单一训练框架及可复现的依赖版本。
4. 优先验证 PointPillars 的船舶三维检测基线，再比较 MVXNet 单相机融合的增益；这是建议，不代表已选定或执行。
5. 图像侧单独对照 YOLOE 预训练分割与 RF-DETR / RTMDet-Ins 的任务微调，保留原实例分割要求。
6. 在世界坐标评估目标中心、尺寸、方向、召回和抖动，记录端到端延迟与显存，再决定 ROS 接入。
7. 甲板几何、可降落性及降落控制另行设计，不在本次研究中添加算法。

本次“学习”明确指目标感知与三维检测；不扩展为强化学习控制，也不要求完整三维场景重建。
雷达仍提供实际距离测量，融合网络学习目标语义、几何及三维框，而非用单目深度替代所有测距。

## 8. 数据、坐标与评测约定

### Scene_Water 当前数据

本地 `/home/htfp/data/Scene_Water_20260805_013651/metadata.yaml` 显示约 640 秒 MCAP 数据：

| 输入 | 话题 | 消息类型 | 条数 |
| --- | --- | --- | --- |
| 图像 | `/left_camera/image/compressed` | `sensor_msgs/msg/CompressedImage` | 5098 |
| 点云 | `/livox/lidar` | `livox_avia_driver/msg/CustomMsg` | 6795 |
| 里程计 | `/fsdk/aircraft_state` | `nav_msgs/msg/Odometry` | 32005 |
| IMU | `/livox/imu` | `sensor_msgs/msg/Imu` | 130435 |

metadata 不提供实例掩膜、三维框、标定真值或各条消息的 frame_id，也不能证明图像与点云已同步。
是否另有标注文件尚未审计；仅凭这个 bag 不能立即开始监督式船舶三维检测训练。

### 可用公开海事数据参考

SeePerSea 提供图像、点云、时间戳、相机/雷达标定及三维标注，有适配 KITTI 的汇总格式。
其兼容格式将 Ship 映射为 Car；接入时须明确恢复船舶语义，不要与真实车辆标签混用。
完整数据需申请，许可证为 CC BY-NC-SA 4.0；本轮未下载数据或核实船舶模型权重。
[作者仓库](https://github.com/dartmouthrobotics/SeePerSea)、[数据申请入口](https://seepersea.github.io/)

它是水面平台视角而非无人机俯视，也不等同于大型船舶甲板实例分割数据。
工程判断：比道路车辆数据更适合用于海事检测预训练/迁移参考，但仍需自采数据标注及验证。
其道路类别映射只是数据兼容，不意味着道路预训练权重已经学会识别船只。

### 坐标和几何边界

- 历史同向安装、单位旋转和零平移仅作物理安装占位；机体轴与相机 optical 轴要分开核验。
  ROS 机体通常是 x 前、y 左、z 上，光学轴是 z 前、x 右、y 下，不能因镜头同向而忽略轴变换。
  [ROS REP-103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)
- `/fsdk/aircraft_state` 的父/子 frame、ENU/NED 约定及传感器到机体外参需要读取消息确认；
  不在配置中猜测 `map` 或 `world` 名称。没有有效变换时不得发布标为世界坐标的结果。
- 模型可以使用局部、重力对齐坐标，训练与推理必须一致；下游输出再变换到世界坐标，
  不直接向车载网络输入未经适配的绝对世界坐标。
- 常用道路模型的中心/尺寸/yaw 框不等于完整六自由度姿态，更不等于船舶甲板平面。
  船舶横滚、纵摇与表面障碍需另行评估，不能从三维框准确率推断降落安全。
- 点云跨帧积累需区分无人机运动与船舶运动；只补偿无人机可能造成目标拖影。

### 评测要求

- 按采集序列、船舶或场景划分训练/验证/测试，避免相邻帧随机分到不同集合造成泄漏。
- 测试集保留独立人工标签；伪标签若使用，也必须区分其来源与人工复核情况。
- 分别统计整船和甲板/平台的框精度、召回、实例掩膜 IoU、误检及连续帧框抖动。
- 三维检测另统计 3D/BEV 框 IoU、中心距离误差、尺寸/航向误差和目标有效点数，按距离及视角分组；
  真值范围不足的样本应标为不可验证，不把人工补全尺寸当作精确实测。
- 测量预处理、推理、后处理与发布总延迟，同时记录显存和输入分辨率。
- 本次查询本机为 T600 Laptop、4 GiB 显存；机载硬件另行确认，不保证 MVXNet 或双模型同驻可实时运行。
  训练硬件需求也须单独测量，不直接套用作者在其他 GPU/TensorRT 下的速度。
- 当前相机内参仍为历史占位值，正式距离评测前需要完成标定与时间戳核对。
